# 1.2.0 测试版技能兼容性

test.3 将 63 项已支持技能接入原生「球员训练 → 技能训练」的自选道具、分类、列表和确认流程，包括普通技能与 ST 技能。保存、删除、退出重进和比赛名单使用同一份球员记录。这里的“可选”表示当前网关具有技能 ID 与比赛参数映射，并能保存及回传；没有把主机上的 SQLite 测试当作手机引擎的技能触发验证。特殊技能的比赛触发条件仍需真机逐项验收。

技能 ID 是 `SKILL_CARD` 枚举，参数位置是 147 项数组中的下标，两者不能混用。沿用交付物中的原生枚举和参数表，不通过修改中文名字来假造原生效果。

## dummy 与尚未支持的技能

用户追加反馈的「瞬发射门」（Snap Strike，前文称「闪电快射」）不在 1.1.1 的随机特殊技能池中；当前仍排除有歧义的 ID 9，不能保证随机获得或自选。「强力抢断」（Power Tackle）尚未找到可信的独立映射，不在可选表中；ID 62「长腿铲抢」不作为它的替代。这两项均在玩家公告中标为暂未开放。已有普通/ST 技能的持久化测试不代表这两项效果已验证。

## 原生槽位与重启修复

当前交付引擎（SHA-256 `2cea0c85344d7d7f295aea1c2353621f02db78dbccd888a0a21a0508ac330659`）实际使用 0～4 表示五个训练槽。旧服务把 0 当追加、其余编号减一，导致玩家依次训练五个槽，保存的却只有四个；即时界面与重开后的记录因此不同。本次按原生编号保存，允许先填写靠后的空槽，原有已保存技能顺序保持不变，已经被旧版本覆盖的选择不能凭空恢复。

原生技能删除会将后面的技能向前移动，最后一槽清空；服务端现在执行相同操作，避免删除后再次训练错位。新登录后的请求计数与上一次登录分开处理，重复网络请求仍只执行一次。完整函数、字段与机器码验收证据见 [原生技能接口记录](NATIVE_SKILL_SELECTOR.md)。

## 证据与验收范围

静态关联审计使用交付物中的 7,094 张卡，排除 2 张未分类异常卡后对 7,092 张逐项比较。74 个参数映射中 64 个与外部缓存布尔字段完全相符。该缓存与卡片组装代码可能共享同一来源，因此相关性不是独立的原生引擎语义证明；特别是 117 与 131 都对应同一批 gameChangingPass 卡，不能据此凭空推导一个新技能。

本地测试覆盖真实临时 SQLite 关库重开、原生技能训练命令、登录/详情/球队快照/比赛参数、同卡不同实例与首发替补换序、五槽位替换、请求重试不重复操作和手动/自动设置保存。已知阵容保存命令经过回归，但没有手机半场操作抓包，不能把该回归等同于原生半场换人实测。

真机验收需记录：所选球员实例、技能及槽位、训练后详情、大退重开、开赛、半场换人后的同一实例详情与实际触发条件。对有歧义的 ID 9/31/70，需对原生技能说明和比赛效果逐项确认后才能正式命名或交换参数映射。
