# test.3 原生界面接入与验证记录

用户要求移除额外的「efootxi 设置」浮层，技能选择和帧率进入游戏原生设置，公告只从右上角通知图标查看；预置球员进入正常球员列表。

## 已完成的改动

- 删除 Java `EfootxiPanel`、原 `HighFrameRate` 浮窗及其生命周期注册，不再往 `GameActivity` 根布局添加常驻按钮，也不再恢复旧浮窗保存的帧率请求。
- 更新页保留项目网址、反馈邮箱和来源说明；公告入口提示使用原生通知图标。原生游戏布局及字体不由 Android 额外设置窗覆盖。
- 启动失败时仍保留完整错误与「复制错误详情」。反馈邮箱按钮直接打开邮件应用；未安装邮件应用时复制邮箱。
- 原生公告改接 `CMD_GET_MAILBOX_INFO`，使用 `news_id`、`readFlag: YES/NO`、`NEWS_TYPE_GLOBAL` 等当前游戏协议字段。旧的 Nyan 示例 `newsId/readFlag: 0/1` 不再作为原生通知正文发送。
- `is_news_popup=NO`、`frequency_type=NONE`；保留主页 `unread_information_count`。只有原生 `CMD_SET_NEWSLIST` 的整数 `news_list` 确认已读，打开列表不直接清除所有未读。已读记录保存到 SQLite，更新公告使用新 ID。
- 预置赠卡位置修复及存档备份详见 [球员迁移](player-migration.md)。正常列表全量快照、保存不变与重启已验证。

## 交付物证据

当前 `libUE4.so` SHA-256 为 `2cea0c85344d7d7f295aea1c2353621f02db78dbccd888a0a21a0508ac330659`。复用已识别的当前 APK、REA 证据及已验证的 Ghidra 12.1.4 直接离线分析流程；此 ARM64 ELF 不在 Windows REA provider 的可用目标范围。聚焦反编译使用 `-readOnly`，没有把静态伪代码当作实际手机行为。

真实 `046_gate_CMD_GET_MAILBOX_INFO_resp.txt` 的 SHA-256 为 `872c597ebe1148ec47d2ac2ad1bac84f57c8eca572b6f6fed31199006026e972`。原生新闻解码器 ELF VA `0x752732c`、新闻列表 `0x7708de0`；已读请求序列化器 `0x77adfdc/0x77ae0a0` 写入 `news_list: int32[]`。主页 `0x7711220` 分别读取未读数量和是否弹出。正文捕获是纯文本，含 CRLF，不依赖远程 HTML。Ghidra 地址需在 ELF VA 上加本次导入偏移 `0x100000`。

临时分析输出位于 `build/native-news-audit/`；11 项公告回归覆盖真实响应字段类型、主页不弹出、逐条已读、重启、全读清零与新 ID 未读。红点实际绘制、点击正文及关闭后的刷新时机仍需手机复测。用户录屏中的白页与旧格式不匹配相符，但不能断言这是该画面唯一原因。
